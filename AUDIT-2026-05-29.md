## FINDINGS (bugs)

### 🔴 CRITICAL #1 — All 7 agent files broken (`SyntaxError`), committed on `main`

**Files:** `services/api/src/shipcomply_api/agents/{cloner,scanner_agent,kg_builder,legal_writer_agent,code_gen_agent,guardrail,audit_agent}.py`

**Symptom:**
```
File ".../agents/cloner.py", line 3
    from __future__ import annotations
SyntaxError: from __future__ imports must occur at the beginning of the file
```

**Root cause:** A `@traced` observability codemod inserted
`from shipcomply_api.observability.langfuse import traced` as **line 1** of each file — above the module docstring and above `from __future__ import annotations`. Python requires `from __future__` to be the first statement after the docstring, so every agent module fails to import.

**Blast radius:** `agents/graph.py` imports all 7 nodes → `get_compiled_graph()` throws → **every scan crashes**. This is the "agents not working." `git status` shows no working-tree changes, so the broken code is committed → the deployed API has the same fault.

**Why API import still passed:** routes import the graph lazily (not at module load), so `main.py` imports fine; the crash only surfaces when a scan runs.

**Fix:** move the `traced` import below `from __future__ import annotations` in all 7 files. *(applied — see Fixes Applied)*

### 🔴 CRITICAL #2 — `pnpm build` fails (web prerender, missing Clerk key)

**Symptom (from `.audit/build.log`):**
```
web:build: Error occurred prerendering page "/_not-found"
web:build: Error: @clerk/clerk-react: Missing publishableKey.
web:build: Export encountered an error on /_not-found/page: /_not-found, exiting the build.
web#build exited (1)
```

**Root cause:** `next build` runs in `apps/web` and only loads env from `apps/web/.env*`. `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` lives only in repo-root `.env`, so `<ClerkProvider>` throws while statically prerendering `/_not-found`.

**Blast radius:** Local `pnpm build` fails; Vercel production build fails the same way unless the env var is set in the Vercel dashboard. The trailing `echo "EXIT $?"` in the diagnostic masked this as "exit 0" at the task level — the real pnpm exit was 1.

**Fix options:** (a) load root `.env` in `apps/web` build, (b) make `/_not-found` not require Clerk, or (c) force-dynamic. *(fix in progress)*

### 🔴 CRITICAL #3 — Scanner detects 0 elements (silent regression)

**File:** `services/api/src/shipcomply_api/scanner/__init__.py`

**Symptom:** `scan_repo(examples/sample-nextjs-app)` returns **0** data elements. Violates the demo invariant ("`scan:sample` always returns ≥1 element").

**Root cause:** `tree_sitter` + `tree_sitter_typescript` are now installed (they weren't when the regex fallback was the proven path). So `_try_treesitter_scan()` returns `True` for every file. But the AST detectors are narrow — only JSX inputs, analytics calls, and `"use server"` params, and the TS grammar misses `.tsx` JSX + bare field identifiers — so the AST pass finds **0** in these files. Because AST "succeeded", the comprehensive **regex fallback was skipped**. The tree-sitter install silently zeroed out detection.

**Evidence (`.audit/scanner-diag.log`):** per-file `ast_used: True | ast_elems: 0 | regex_elems: 3/5/5`.

**Fix:** fall back to regex whenever the AST pass detects nothing in a file. *(applied — scanner now returns 5 elements: name, email, phone, address, dob.)*

### 🔴 CRITICAL #4 — CLI crashes on launch (this is the "npm not working")

**Symptom (`.audit/scan-sample.log`):**
```
TypeError: Cannot read properties of undefined (reading 'ReactCurrentOwner')
  at react-reconciler@0.29.2 ... at ink@5.2.1/build/reconciler.js
```

**Root cause:** Ink 5 + React 19 incompatibility. `apps/cli` pinned `react ^19` + `ink ^5`. Ink 5's bundled `react-reconciler@0.29` reads `ReactSharedInternals.ReactCurrentOwner`, which React 19 removed. Ink 5's peer range (`react >=18`) is too loose and lets React 19 resolve. Every CLI command crashes at Ink init → `npx shipcomply` is dead.

**Fix:** pin `apps/cli` to `react ^18.3.1` + `@types/react ^18.3.12` (Ink 5's supported major) and reinstall. *(applied — see Fixes Applied; verification pending install.)*
